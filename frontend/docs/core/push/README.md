# Архитектура и Документация Ядра: Модуль `push`

## 1. Для чего и зачем нужен этот модуль?
В странах с жесткой цензурой (РФ, Иран, Китай) власти блокируют серверы мессенджеров, но **никогда не блокируют системные Push-уведомления Google (FCM — Firebase Cloud Messaging)**.
Если заблокировать порты Google FCM (5228-5230 TCP), перестанут работать уведомления банков (Сбер, Т-Банк, Kaspi), такси, госуслуг и доставки. Это вызовет паралич гражданской инфраструктуры.

Модуль `push` использует системный канал Push-уведомлений как **неуязвимый стеганографический командный шлюз** и шлюз фоновой расшифровки сообщений.

---

## 2. Что делает модуль (Анатомия и Архитектура)?

### 1. Криптографическая стеганография (Скрытый блоб)
Для серверов Google и цензора пуш выглядит как абсолютно случайный мусор:
```json
{
  "to": "token...",
  "data": { "p": "7f8b91c... (зашифрованный блоб XChaCha20-Poly1305)" }
}
```
Ни Google, ни оператор связи не знают отправителя, получателя или тип команды.

### 2. Фоновая расшифровка сообщений от контактов (`IncomingMessage`)
Когда приходит Push с сообщением от Алисы или Боба:
- ОС будит AnonGram в фоне на несколько секунд.
- Модуль `push` расшифровывает сообщение сессионным ключом.
- Ядро извлекает чистый текст и отдает его локальному компоненту уведомлений ОС. 
- На экране отображается баннер с сообщением, при этом Google не увидел ни одного слова переписки.

### 3. Исполнение скрытых приказов ядра
- **`RotateServerEndpoint`**: экстренная смена IP-адреса или домена сервера в модуле `network` прямо на лету при блокировке старого адреса.
- **`WakeAndSync`**: тихое пробуждение фонового процесса для скачивания очереди сообщений.
- **`PanicWipe`**: сигнал экстренного удаленного самоуничтожения (стирание базы данных и OTP-блокнотов при задержании).

### 4. Защита от Replay-атак
Каждый пакет содержит монотонный 64-битный счетчик (`nonce`). Повторная отправка перехваченного цензором пуша немедленно отбрасывается с ошибкой `ReplayDetected`.
