# Архитектура и Документация Ядра: Модуль `storage`

## 1. Для чего и зачем нужен этот модуль?
Криминалистические комплексы (Cellebrite UFED, GrayKey) извлекают базы данных SQLite большинства мессенджеров (Signal, Telegram, WhatsApp), если устройство выключено или находится в режиме BFU/AFU (Before/After First Unlock).
Обычные базы данных хранят индексы, кэш и переписку в открытом виде или со слабым шифрованием, ключ от которого лежит в соседнем XML-файле shared preferences.

Модуль `storage` реализует **полноценное постраничное аппаратное шифрование хранилища и функцию гарантированного физического уничтожения (Panic Wipe)**.

---

## 2. Что делает модуль (Анатомия и Архитектура)?

### 1. Постраничное шифрование (Page-Level AEAD)
- Все записи базы данных (сообщения, контакты, параметры профиля) шифруются на лету алгоритмом **XChaCha20-Poly1305**.
- Ключ шифрования базы данных существует **только в оперативной памяти** и оборачивается в трейт `ZeroizeOnDrop`.
- Если устройство заблокировано или выключено, на диске остается только зашифрованный бинарный блоб с контрольными суммами Poly1305.

### 2. Защита от повреждения данных
- При каждой записи на диск вызывается принудительный системный вызов `sync_data()`, гарантирующий сброс буферов файловой системы ОС на физический накопитель.

### 3. Экстренное уничтожение данных (`panic_wipe`)
При вызове функции самоуничтожения (по паролю под принуждением или по скрытому сигналу из модуля `push`):
1. Ключ в оперативной памяти затирается нулями.
2. Вся оперативная память кэша затирается нулями.
3. Файл базы данных на накопителе перезаписывается криптографическими нулями `0x00` по всей длине с системным вызовом `sync_data()`.
4. Файл удаляется из файловой системы.
Даже при снятии микросхем памяти в лаборатории восстановить переписку физически невозможно.
