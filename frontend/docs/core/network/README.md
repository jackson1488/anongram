# Архитектура и Документация Ядра: Модуль `network`

## 1. Для чего и зачем нужен этот модуль?
Обычные мессенджеры жестко зашивают в бинарный код IP-адреса и домены своих серверов. 
Это приводит к катастрофическим последствиям при блокировках:
1. **Жесткий бан цензором**: Цензор (РКН/ТСПУ/GFW) открывает код клиента через `strings libcore.so`, видит список IP и мгновенно отправляет их в черный список.
2. **Паралич приложения**: Если серверный IP заблокирован, пользователю нужно скачать обновление из Google Play или App Store. Но сами магазины приложений в этот момент тоже могут быть заблокированы!
3. **Блокировка UDP**: Цензоры часто замедляют или полностью вырезают протокол UDP, что ломает звонки и быстрый обмен сообщениями.

Модуль `network` решает эту проблему благодаря архитектуре **Zero-Hardcoded Endpoints (в ядре нет ни одного зашитого адреса)** и **Dual-Channel Transport (TCP + UDP)**.

---

## 2. Что делает модуль (Анатомия и Архитектура)?

### 1. Универсальный ServerEndpoint (`endpoint.rs`)
Модуль поддерживает любой формат адреса, переданный в рантайме:
- `130.162.254.32` (чистый IPv4)
- `130.162.254.32:8443` (IP + нестандартный порт)
- `cloud.neongram.space` (домен)
- `cloud.neongram.space:443/api/v1` (домен + порт + базовый путь REST API)
- `wss://relay.anongram.net:9000/stream` (WebSocket-туннель)
- `[2001:db8::1]:9000` (IPv6)

### 2. Двойной канал: TCP Stream + UDP Datagram (`transport.rs`)
- **UDP Datagram**: приоритетный канал для максимальной скорости передачи, низкого ping и звонков.
- **TCP Stream**: надежный потоковый канал с гарантией доставки сообщений.
- **DPI Failover**: если ядро фиксирует деградацию UDP-пакетов (пропадание или таймауты), оно бесшовно переключается на TCP без прерывания соединения пользователя.

### 3. Мгновенная динамическая ротация адресов из Push
При поступлении приказа от модуля `push` ядро вызывает:
`network.rotate_endpoint_from_str("новый_адрес:порт")`
Сетевой стек переподключается на лету, не требуя перезапуска приложения.

---

## 3. Изоляция и Надежность
* Модуль `network` изолирован от VPN-туннелей и криптографических блокнотов OTP. 
* Ошибки строго типизированы в `NetworkError`:
  - `Unconfigured` (эндпоинт еще не задан)
  - `InvalidEndpoint`
  - `ConnectionFailed`
  - `TransmissionError`
