# Модульная Верификация Собеседников (Anti-MITM) и Гибридные Групповые Чаты (Double Ratchet + Sender Keys)

## Архитектура Безопасности AnonGram

Документ описывает реализацию двух критических подсистем ядра AnonGram:
1. **Модульная система Anti-MITM верификации** (`crates/security/src/verification/`)
2. **Пост-квантовый Double Ratchet и Гибридные Групповые Чаты** (`crates/crypto/src/ratchet.rs` и `crates/crypto/src/group/`)

## 1. Модульная Anti-MITM Верификация

Для защиты от атак типа «Человек посередине» (Man-in-the-Middle) реализованы 4 полностью независимых, отключаемых модуля:

```
┌────────────────────────────────────────────────────────────────────────┐
│                   4 МОДУЛЯ ВЕРИФИКАЦИИ СОБЕСЕДНИКА                     │
├────────────────────────────────────────────────────────────────────────┤
│                                                                        │
│  [1. 60 Цифр (NumericFingerprint)]    [2. QR-код (QrSafetyScanner)]    │
│  - 12 блоков по 5 цифр.               - Генерация QR для экрана.       │
│  - Симметрично и канонично.           - Валидация скана камерой.       │
│  - Сверка голосом при звонке.         - Статус: Verified 🛡️.           │
│                                                                        │
│  [3. Сторож Ключей (KeyChangeGuard)]  [4. Реестр (ServerWitness)]      │
│  - Обнаружение подмены ключа.         - Проверка дерева Меркла.        │
│  - Блокировка отправки сообщений.     - Фоновый аудит прозрачности.    │
│  - Защита от взломанного сервера.     - Отключается в настройках.      │
│                                                                        │
└────────────────────────────────────────────────────────────────────────┘
```

1. **`NumericFingerprint` (60 цифр)**:
   - Вычисляет канонический 60-значный отпечаток из открытых ключей и идентификаторов участников по формуле:
     $$H = \text{SHA-512}(\min(K_A, K_B) \mathbin{\Vert} \max(K_A, K_B) \mathbin{\Vert} \min(ID_A, ID_B) \mathbin{\Vert} \max(ID_A, ID_B))$$
   - Форматируется в 12 блоков по 5 цифр (`12458 98214 55120 ...`), гарантированно идентичен у обоих собеседников независимо от того, кто открыл экран.
2. **`QrSafetyScanner` (Скан QR при встрече)**:
   - Упаковывает параметры в защищенный бинарный payload `[AGQR || version || peer_id || public_key || timestamp]`.
   - При считывании камерой мгновенно проверяет совпадение и переводит контакт в статус `Verified`.
3. **`KeyChangeGuard` (Сторож подмены ключей)**:
   - Если сервер или MITM пытается заменить открытый ключ контакта, guard детектирует несоответствие.
   - В политике `BlockSending` отправка сообщений немедленно блокируется с требованием явного подтверждения пользователя.
4. **`ServerTransparencyWitness`**:
   - Фоновая сверка открытого ключа с криптографическим журналом прозрачности (Certificate Transparency аналог).

## 2. Пост-квантовый Double Ratchet на Чистом Rust

Реализация не использует сторонний `libsignal`, что исключает C-уязвимости и обеспечивает поддержку пост-квантовых алгоритмов (ML-KEM / ML-DSA).

### Два независимых храповика:
1. **Симметричный храповик (KDF Chain Step)**:
   - Срабатывает на **каждое отдельное сообщение**.
   - Даже при отправке серии сообщений подряд каждое сообщение шифруется свежим 256-битным ключом:
     $$K_{msg} = \text{HKDF-Expand}(K_{chain}, \text{"ANONGRAM/message-key"})$$
     $$K_{chain}^{next} = \text{HKDF-Expand}(K_{chain}, \text{"ANONGRAM/chain-advance"})$$
   - Отработанный $K_{msg}$ немедленно стирается из памяти (`zeroize`).
2. **Асимметричный храповик (DH/KEM Ratchet Step)**:
   - Срабатывает при каждом ответе собеседника, пересчитывая корневой ключ $K_{root}$ и обновляя цепочки отправителя и получателя (Post-Compromise Security).

## 3. Гибридные Групповые Чаты (до 30 и от 30 до 300+ человек)

```
┌────────────────────────────────────────────────────────────────────────┐
│                   ГИБРИДНЫЙ РЕЖИМ ГРУППОВЫХ ЧАТОВ                      │
├────────────────────────────────────────────────────────────────────────┤
│                                                                        │
│  [StrictPairwise] (до 30 участников):                                  │
│  - Персональный Double Ratchet для каждого участника.                  │
│  - Максимальная изоляция и паранойя.                                   │
│                                                                        │
│  [SenderKeys] (от 30 до 300+ участников):                              │
│  - Протокол Sender Keys (Signal v2).                                   │
│  - 1 шифрование на группу, трафик и нагрузка на батарею 1x.            │
│                                                                        │
│  [Adaptive] (Порог перехода 31):                                       │
│  - При добавлении 31-го участника:                                     │
│    1. Очистка очереди и доставка старых сообщений.                     │
│    2. Физическое зануление (Zeroize) старых попарных ключей в RAM.     │
│    3. Генерация новых Sender Keys.                                     │
│    4. Системное уведомление в чате.                                    │
│                                                                        │
└────────────────────────────────────────────────────────────────────────┘
```

### Безопасный протокол перехода ($30 \to 31$):
- При достижении 31 участника старые попарные ключи стираются из памяти.
- Пользователи видят сервисное сообщение: *«В группе более 30 участников. Режим шифрования автоматически переключен на высокоскоростной Sender Keys. Старые ключи уничтожены.»*
- При сокращении участников до $\le 30$ ядро разблокирует возможность обратного возврата (даунгрейда) в режим `StrictPairwise`.
