# Архитектура и Документация Ядра: Модуль `security`

## 1. Для чего и зачем нужен этот модуль?
Даже самое сильное квантово-стойкое шифрование бесполезно, если:
1. Злоумышленник или силовик получает физический доступ к телефону и подбирает слабый пароль по словарю.
2. Украденный или потерянный телефон продолжает получать сообщения от собеседников, потому что нет механизма отзыва устройства.

Модуль `security` обеспечивает локальную защиту устройства, аутентификацию и реестр доверенных девайсов.

---

## 2. Что делает модуль (Анатомия и Архитектура)?

### 1. Деривация мастер-пароля (`kdf.rs`)
- Использует стойкую к GPU/ASIC-перебору функцию вывода ключа (KDF) с уникальной 128-битной криптографической солью (`salt`).
- Синтезирует 256-битный ключ для разблокировки локальной зашифрованной базы данных (`storage`).

### 2. Мост биометрии и аппаратного анклава (`biometrics.rs`)
- Интегрируется с аппаратными чипами безопасности (Titan M на Google Pixel, Secure Enclave на Apple).
- При успешном прикладывании пальца или Face ID аппаратный чип выдает ключ расшифровки сессии.
- Все ключи в памяти защищены очисткой `zeroize` при блокировке экрана.

### 3. Реестр доверенных устройств и отзыв (`device.rs`)
- Хранит список авторизованных устройств пользователя (`device_id`, имя, открытый ключ устройства).
- **Мгновенный отзыв скомпрометированного устройства (`revoke_device`)**:
  - Если планшет или телефон утерян, владелец с доверенного устройства отзывает его ID.
  - Устройство помечается как `is_revoked = true`.
  - Попытка расшифровать сообщения или отправить команды с отозванного устройства немедленно отклоняется с ошибкой `DeviceRevoked`.
