# Архитектура и Документация Ядра: Модуль `control` (Центральный Оркестратор Ядра)

## 1. Для чего и зачем нужен этот модуль?
В модульной микроядерной архитектуре каждый компонент (`push`, `network`, `storage`, `otp`, `security`) изолирован и не имеет прямых жестких связей с соседями. Это исключает циклические зависимости и спагетти-код.

Однако в критических ситуациях ядру требуется **центральный командный центр (Command Orchestrator)**:
1. **Каскадное экстренное уничтожение (Cascading Panic Wipe)**: Когда через Google FCM / APNs прилетает скрытый приказ на самоуничтожение, необходимо в строго определенном порядке разорвать сокеты, затереть блокноты на диске, стереть базу данных и сбросить ключи в RAM.
2. **Маршрутизация скрытых Push-приказов**: Распределение входящих команд между модулем сети (`network.rotate_endpoint`), хранилищем (`storage.put`) и интерфейсом пользователя.

Модуль `control` выполняет роль центрального дирижера ядра AnonGram.

---

## 2. Что делает модуль (Анатомия и Архитектура)?

### 1. `KernelCommander` (`commander.rs`)
Управляет жизненным циклом ядра (`CoreLifecycleState`):
- `Active` — нормальный режим работы.
- `RotatingEndpoint` — переходный режим смены IP/домена сервера.
- `Purged` — терминальное состояние после выполнения Panic Wipe (все операции заблокированы).

### 2. Протокол Каскадного Самоуничтожения (`execute_cascading_purge`)
Выполняется за 5 миллисекунд:
1. **Сетевая изоляция (`network`)**: Сброс всех сетевых менеджеров, закрытие TCP и UDP сокетов, стирание буферов сокетов.
2. **Физическое затирание OTP-блокнотов (`otp`)**: Проход по всем зарегистрированным путям блокнотов `.pad`, побайтовая перезапись файла криптографическими нулями `0x00` по всей длине с системным вызовом `sync_data()`, затем удаление файла `remove_file()`.
3. **Уничтожение локальной БД (`storage`)**: Вызов `storage.panic_wipe()`, затирание оперативной памяти кэша, зануление файла базы на носителе и его удаление.
4. **Блокировка состояния**: Ядро переходит в статус `Purged`. Все последующие попытки вызова функций ядра мгновенно отклоняются с ошибкой `ControlError::Purged`.

---

## 3. Обработка Push-приказов
Метод `commander.handle_encrypted_push(key, encrypted_blob)`:
- Расшифровывает полезную нагрузку через `crates/push`.
- Проверяет защиту от повторов (Replay Attacks).
- В зависимости от приказа:
  - `IncomingMessage`: сохраняет зашифрованное сообщение в локальную БД.
  - `RotateServerEndpoint`: на лету обновляет адрес в `crates/network`.
  - `PanicWipe`: запускает каскадный протокол уничтожения.
